# Oracle to PostgreSQL Schema Mapping Guide

## Overview

This document describes the heterogeneous database migration from Oracle Database to Amazon Aurora PostgreSQL as part of StreamForge Phase 6. It covers data type mappings, syntax conversions, and manual remediation requirements.

---

## Data Type Mappings

### Numeric Types

| Oracle Type | PostgreSQL Type | Notes |
|-------------|-----------------|-------|
| `NUMBER` | `INTEGER` | For integers without decimals |
| `NUMBER(10)` | `BIGINT` | For large integers |
| `NUMBER(12,2)` | `NUMERIC(12,2)` | Preserves precision and scale |
| `NUMBER(3,2)` | `NUMERIC(3,2)` | For percentages (e.g., 0.15) |
| `BINARY_FLOAT` | `REAL` | 4-byte floating point |
| `BINARY_DOUBLE` | `DOUBLE PRECISION` | 8-byte floating point |

### String Types

| Oracle Type | PostgreSQL Type | Notes |
|-------------|-----------------|-------|
| `VARCHAR2(n)` | `VARCHAR(n)` | Direct mapping |
| `CHAR(n)` | `CHAR(n)` | Fixed-length, blank-padded |
| `NVARCHAR2(n)` | `VARCHAR(n)` | PostgreSQL uses UTF-8 by default |
| `CLOB` | `TEXT` | Unlimited text storage |
| `LONG` | `TEXT` | Oracle LONG is deprecated |

### Date and Time Types

| Oracle Type | PostgreSQL Type | Notes |
|-------------|-----------------|-------|
| `DATE` | `TIMESTAMP(0)` | Oracle DATE includes time |
| `TIMESTAMP` | `TIMESTAMP` | Direct mapping |
| `TIMESTAMP WITH TIME ZONE` | `TIMESTAMPTZ` | Timezone-aware |
| `INTERVAL DAY TO SECOND` | `INTERVAL` | Duration type |

### Binary Types

| Oracle Type | PostgreSQL Type | Notes |
|-------------|-----------------|-------|
| `RAW(n)` | `BYTEA` | Binary data |
| `BLOB` | `BYTEA` | Large binary objects |

### Special Types

| Oracle Type | PostgreSQL Type | Notes |
|-------------|-----------------|-------|
| `ROWID` | N/A | PostgreSQL uses `ctid` internally |
| `UROWID` | N/A | No direct equivalent |

## Sequences and Auto-Increment

### Oracle

```sql
CREATE SEQUENCE customers_seq START WITH 1000 INCREMENT BY 1;

CREATE TRIGGER customers_bir
BEFORE INSERT ON CUSTOMERS
FOR EACH ROW
BEGIN
    IF :new.customer_id IS NULL THEN
        :new.customer_id := customers_seq.NEXTVAL;
    END IF;
END;
```

### PostgreSQL (Option 1: IDENTITY)

```sql
CREATE TABLE CUSTOMERS (
    customer_id BIGINT GENERATED BY DEFAULT AS IDENTITY (START WITH 1000),
    -- other columns
);
```

### PostgreSQL (Option 2: SEQUENCE)

```sql
CREATE SEQUENCE customers_seq START WITH 1000 INCREMENT BY 1;

CREATE TABLE CUSTOMERS (
    customer_id BIGINT DEFAULT nextval('customers_seq'),
    -- other columns
);
```

**Recommendation:** Use `GENERATED BY DEFAULT AS IDENTITY` for new migrations as it's SQL standard-compliant.

## Triggers

### Oracle Trigger Syntax

```sql
CREATE OR REPLACE TRIGGER customers_bir
BEFORE INSERT ON CUSTOMERS
FOR EACH ROW
BEGIN
    :new.created_date := SYSDATE;
    :new.updated_date := SYSDATE;
END;
/
```

### PostgreSQL Trigger Syntax

```sql
CREATE OR REPLACE FUNCTION customers_before_insert()
RETURNS TRIGGER AS $$
BEGIN
    NEW.created_date := CURRENT_TIMESTAMP;
    NEW.updated_date := CURRENT_TIMESTAMP;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER customers_bir
BEFORE INSERT ON CUSTOMERS
FOR EACH ROW
EXECUTE FUNCTION customers_before_insert();
```

**Key Differences:**
- PostgreSQL requires separate function definition
- `:new` becomes `NEW` (no colon)
- Must `RETURN NEW` or `RETURN OLD`
- Function language is `plpgsql`

## Stored Procedures and Functions

### PL/SQL vs PL/pgSQL

| Feature | Oracle PL/SQL | PostgreSQL PL/pgSQL |
|---------|---------------|---------------------|
| Variable declaration | `v_var NUMBER;` | `v_var INTEGER;` |
| Assignment | `:=` | `:=` |
| String concatenation | `||` | `||` |
| NULL handling | `NVL(val, default)` | `COALESCE(val, default)` |
| Current date/time | `SYSDATE` | `CURRENT_TIMESTAMP` |
| Exception handling | `EXCEPTION WHEN` | `EXCEPTION WHEN` |
| Output | `DBMS_OUTPUT.PUT_LINE()` | `RAISE NOTICE` |
| Custom errors | `RAISE_APPLICATION_ERROR(-20001, msg)` | `RAISE EXCEPTION '%', msg;` |

### Procedure Conversion Example

**Oracle:**
```sql
CREATE OR REPLACE PROCEDURE calculate_order_total(
    p_order_id IN NUMBER,
    p_total OUT NUMBER
) AS
BEGIN
    SELECT NVL(SUM(line_total), 0)
    INTO p_total
    FROM ORDER_ITEMS
    WHERE order_id = p_order_id;
END;
/
```

**PostgreSQL:**
```sql
CREATE OR REPLACE PROCEDURE calculate_order_total(
    p_order_id IN BIGINT,
    INOUT p_total NUMERIC DEFAULT 0
) AS $$
BEGIN
    SELECT COALESCE(SUM(line_total), 0)
    INTO p_total
    FROM ORDER_ITEMS
    WHERE order_id = p_order_id;
END;
$$ LANGUAGE plpgsql;
```

**Key Changes:**
- `NUMBER` → `BIGINT` or `NUMERIC`
- `OUT` parameters → `INOUT` (PostgreSQL procedures)
- `NVL` → `COALESCE`
- Add `LANGUAGE plpgsql`

### Function Conversion Example

**Oracle:**
```sql
CREATE OR REPLACE FUNCTION get_customer_credit_status(
    p_customer_id IN NUMBER
) RETURN VARCHAR2 AS
    v_status VARCHAR2(50);
BEGIN
    -- logic here
    RETURN v_status;
END;
/
```

**PostgreSQL:**
```sql
CREATE OR REPLACE FUNCTION get_customer_credit_status(
    p_customer_id IN BIGINT
) RETURNS VARCHAR(50) AS $$
DECLARE
    v_status VARCHAR(50);
BEGIN
    -- logic here
    RETURN v_status;
END;
$$ LANGUAGE plpgsql;
```

**Key Changes:**
- `RETURN VARCHAR2` → `RETURNS VARCHAR`
- Variables declared in `DECLARE` block
- Add `LANGUAGE plpgsql`

## Packages

Oracle packages have no direct equivalent in PostgreSQL. Convert to:

1. **Schema-based organization** - group related functions in a schema
2. **Multiple functions** - split package procedures/functions into individual functions
3. **Table-based state** - use temporary tables for package variables

**Oracle Package:**
```sql
CREATE OR REPLACE PACKAGE order_management AS
    PROCEDURE create_order(...);
    PROCEDURE add_order_item(...);
    FUNCTION get_order_status(...) RETURN VARCHAR2;
END order_management;
/
```

**PostgreSQL Equivalent:**
```sql
-- Create schema for organization
CREATE SCHEMA order_management;

-- Individual functions in the schema
CREATE FUNCTION order_management.create_order(...) ...;
CREATE FUNCTION order_management.add_order_item(...) ...;
CREATE FUNCTION order_management.get_order_status(...) RETURNS VARCHAR ...;
```

## Views

### Standard Views

Direct mapping - syntax is nearly identical.

**Oracle:**
```sql
CREATE OR REPLACE VIEW v_order_summary AS
SELECT o.order_id, c.customer_name
FROM ORDERS o
JOIN CUSTOMERS c ON o.customer_id = c.customer_id;
```

**PostgreSQL:**
```sql
CREATE OR REPLACE VIEW v_order_summary AS
SELECT o.order_id, c.customer_name
FROM ORDERS o
JOIN CUSTOMERS c ON o.customer_id = c.customer_id;
```

### Materialized Views

**Oracle:**
```sql
CREATE MATERIALIZED VIEW mv_sales_by_region
BUILD IMMEDIATE
REFRESH COMPLETE ON DEMAND
AS SELECT ...;
```

**PostgreSQL:**
```sql
CREATE MATERIALIZED VIEW mv_sales_by_region
AS SELECT ...;

-- Manual refresh required
REFRESH MATERIALIZED VIEW mv_sales_by_region;
```

**Key Differences:**
- PostgreSQL doesn't support automatic refresh
- No `BUILD IMMEDIATE` clause
- Use `pg_cron` or application logic for scheduled refresh

## SQL Functions and Operators

| Oracle | PostgreSQL | Notes |
|--------|------------|-------|
| `NVL(val, default)` | `COALESCE(val, default)` | Null handling |
| `NVL2(val, if_not_null, if_null)` | `CASE WHEN val IS NOT NULL THEN ... END` | Conditional |
| `DECODE(...)` | `CASE WHEN ... END` | Use CASE expression |
| `SYSDATE` | `CURRENT_TIMESTAMP` or `NOW()` | Current timestamp |
| `TO_CHAR(date, format)` | `TO_CHAR(date, format)` | Similar but format strings differ |
| `TO_DATE(str, format)` | `TO_TIMESTAMP(str, format)::DATE` | String to date |
| `SUBSTR(str, pos, len)` | `SUBSTRING(str FROM pos FOR len)` | Substring extraction |
| `INSTR(str, substr)` | `POSITION(substr IN str)` | Find substring |
| `LENGTH(str)` | `LENGTH(str)` | String length |
| `ROWNUM` | `ROW_NUMBER() OVER ()` or `LIMIT` | Row limiting |
| `DUAL` table | Not needed | Remove FROM DUAL |

### Date Format Codes

| Oracle Format | PostgreSQL Format | Result |
|---------------|-------------------|--------|
| `YYYY` | `YYYY` | 4-digit year |
| `MM` | `MM` | 2-digit month |
| `DD` | `DD` | 2-digit day |
| `HH24` | `HH24` | 24-hour |
| `MI` | `MI` | Minutes |
| `SS` | `SS` | Seconds |
| `MON` | `Mon` | Month abbreviation |

## Unsupported Oracle Features

The following Oracle features have no direct PostgreSQL equivalent and require manual remediation:

### 1. CONNECT BY Hierarchical Queries

**Oracle:**
```sql
SELECT employee_id, manager_id, LEVEL
FROM EMPLOYEES
START WITH manager_id IS NULL
CONNECT BY PRIOR employee_id = manager_id;
```

**PostgreSQL (Use Recursive CTE):**
```sql
WITH RECURSIVE emp_hierarchy AS (
    SELECT employee_id, manager_id, 1 AS level
    FROM EMPLOYEES
    WHERE manager_id IS NULL
    UNION ALL
    SELECT e.employee_id, e.manager_id, eh.level + 1
    FROM EMPLOYEES e
    JOIN emp_hierarchy eh ON e.manager_id = eh.employee_id
)
SELECT * FROM emp_hierarchy;
```

### 2. MERGE Statement (Before PostgreSQL 15)

**Oracle:**
```sql
MERGE INTO target USING source ON (condition)
WHEN MATCHED THEN UPDATE SET ...
WHEN NOT MATCHED THEN INSERT ...;
```

**PostgreSQL 15+:**
```sql
MERGE INTO target USING source ON (condition)
WHEN MATCHED THEN UPDATE SET ...
WHEN NOT MATCHED THEN INSERT ...;
```

**PostgreSQL <15 (Use INSERT ON CONFLICT):**
```sql
INSERT INTO target (...)
VALUES (...)
ON CONFLICT (key_column) DO UPDATE SET ...;
```

### 3. Oracle-Specific Hints

Remove or replace with PostgreSQL configuration:
- `/*+ INDEX(...) */` - PostgreSQL optimizer handles index selection
- `/*+ PARALLEL(...) */` - Use `max_parallel_workers_per_gather`

### 4. ROWID

No direct equivalent. Use primary keys instead.

### 5. External Tables

Use PostgreSQL Foreign Data Wrappers (FDW) like `file_fdw`.

## Manual Conversion Checklist

After AWS SCT automated conversion:

- [ ] Review all triggers - convert to PostgreSQL function syntax
- [ ] Convert packages to schemas with individual functions
- [ ] Replace `NVL` with `COALESCE`
- [ ] Replace `SYSDATE` with `CURRENT_TIMESTAMP` or `NOW()`
- [ ] Convert `ROWNUM` to `ROW_NUMBER()` or `LIMIT`
- [ ] Remove `FROM DUAL`
- [ ] Convert hierarchical queries to recursive CTEs
- [ ] Update date format strings in `TO_CHAR`
- [ ] Convert `RAISE_APPLICATION_ERROR` to `RAISE EXCEPTION`
- [ ] Convert `DBMS_OUTPUT.PUT_LINE` to `RAISE NOTICE`
- [ ] Test all stored procedures and functions
- [ ] Validate constraint behavior
- [ ] Test materialized view refresh logic
- [ ] Update application connection strings
- [ ] Update application SQL dialect

## Performance Considerations

### Indexes

- PostgreSQL benefits from covering indexes
- Consider partial indexes: `WHERE condition`
- Use `INCLUDE` clause for index-only scans (PostgreSQL 11+)

### Statistics

Update table statistics after migration:
```sql
ANALYZE table_name;
```

### Autovacuum

Configure autovacuum thresholds for high-update tables.

---

## Migration Best Practices

1. **Test converted schema in non-production first**
2. **Validate all constraints after data load**
3. **Re-create indexes after bulk load for performance**
4. **Update statistics with ANALYZE**
5. **Test all stored procedures with realistic data**
6. **Monitor replication lag during CDC**
7. **Keep Oracle source read-only during cutover**
8. **Validate row counts and checksums**
9. **Test application connectivity before cutover**
10. **Have rollback plan ready**
